## Expanded source/browser QA

The final isolated run of `npm run test:e2e:mobile` passed all 17 cases in 1.2 minutes against the frozen source and a fresh synthetic backend. It includes actual successful fixture generation/hydration/mutation responses, local reopen/progress, favorite hydration, applied cuisine/atmosphere and avoided IDs, hard zero-budget estimates, opt-in reminder fallback, denied browser location, and forward/back question state with synchronized accessible progress. Pending generation and offline edits retain state; cancelled/failed Saved unlock retries leave the original references unchanged and only successful explicit recovery commits unlocked stops.

WCAG A/AA Axe checks passed for Explore, Saved, Profile, planner, itinerary, selected coral marker and Day, plus the new personal-preferences, diagnostic-report, editing and Saved-recovery views. The 28 reviewed RN Web captures include five portrait dimensions and a clearly labeled 200% browser text sample. Native fontScale, actual map/attribution, assistive focus, keyboard, haptics, gesture navigation and OS permission/delivery behavior remain separate checks.

The successful complete-prompt case explicitly mocks validated `/api/intent` because no OpenAI credential exists. The diagnostics case exercises the actual unavailable intent service and proves report content excludes the submitted private prompt/email/coordinates/token-like text, then persists clearing across reload. No cloud message or diagnostic Share is sent.

## Required native checks

- Safe area, keyboard avoidance and reachable controls at 375 × 667, 360 × 800, 390 × 844, 412 × 915 and 430 × 932 equivalents; smallest supported iPhone/Android device.
- Android hardware back/pop behavior, gesture navigation insets, notification channel and tap response, app process restore.
- iOS native navigation, foreground-location accuracy/revoke, notification behavior, app switcher/process restore and deep-link recovery.
- Permission prompts appear only after the explicit relevant action; no background location, microphone or exact-alarm request.
- Large text, screen-reader focus/labels/state, contrast and reduced motion; no important content depends only on color/haptics.
- Map attribution visible above sheets; real photos attributed; no simulated map/navigation presented as live.
- Provider timeout/denial and no-network editing leave plan state intact; cloud/live integrations verified with real credentials.
- Signed preview install and production binary validation; reviewed privacy/disclosure/legal material and confirmed app IDs before submission.

## Release blockers

Hosted native compilation is available and has succeeded for the initial source; final-source emulator/simulator journeys remain verification work, not a credential blocker. Signed physical-device/store distribution requires confirmed identifiers, developer accounts and signing. Live maps/planning/photos require billed and correctly restricted Google APIs plus an OpenAI key/model. Cloud sync/share needs hosted Supabase migration/auth redirects/SMTP and actual user validation. Production costly APIs require Redis protection. Public release additionally needs approved privacy/terms and final disclosure review. Full in-app turn-by-turn remains outside this beta until the RN/Expo/Google native combination is actually compatible and tested.
