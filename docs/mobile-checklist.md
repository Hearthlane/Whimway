The actual Debug screenshot also shows an Expo error overlay across the tabs. Metro identifies `ERR_NOTIFICATIONS_KEYCHAIN_ACCESS: Keychain access failed: A required entitlement isn't present` in Expo Notifications' import-time server-registration lookup. The SDK's `SecItemCopyMatching` query uses the app's default access group; this simulator build used `CODE_SIGNING_ALLOWED=NO`. Missing simulator signing/Keychain entitlements is the evidence-based repair hypothesis, to be validated rather than hidden with warning suppression. Apple documents that default Keychain access groups derive from the app's signed entitlements. [Apple Keychain access groups](https://developer.apple.com/documentation/security/sharing-access-to-keychain-items-among-a-collection-of-apps), [entitlements and signatures](https://developer.apple.com/documentation/bundleresources/entitlements).

`docs/screenshots/native-ios/debug-keychain-warning-99228dd.png` preserves the observed overlay. The largest content-size category was recorded as `accessibility-extra-extra-extra-large`, but that boot capture also shows a clipped wordmark and very large hero wrapping mid-word; no large-text journey or reachability pass is claimed. Simulator-signing, tab-selector and large-font follow-up verification remain open. The successful unsigned Release Explore screenshot is a separate launch/visual observation, not proof that Keychain-backed services work.
